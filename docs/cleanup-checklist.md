## 4. 정리 순서

순서가 중요함. 다른 리소스가 쓰고 있는 것은 지울 수 없기 때문에, 위에 있는 것(서버)부터 아래에 있는 것(네트워크) 순서로 지움.

### 단계 1. EC2 인스턴스 종료 — `b3-1-web`

- [ ] EC2 > 인스턴스 > `b3-1-web` 선택 > 인스턴스 상태 > 인스턴스 종료(Terminate)
- 왜 먼저: 보안 그룹, 서브넷, 인터넷 게이트웨이를 모두 이 서버가 쓰고 있음. 서버가 없어져야 나머지를 지울 수 있음.
- 화면에서 확인할 것: 인스턴스 상태가 "종료됨(Terminated)". 퍼블릭 IP 칸이 비어 있음.
- 참고: 종료된 인스턴스는 한동안(보통 1시간쯤) 목록에 남아 있다가 사라짐. 정상임.
- 증빙: `e05-ec2-terminated.png`
- 권한: `ec2:TerminateInstances` 허용됨.
- 확인 시각:
- 결과:

### 단계 2. EBS 볼륨 확인 — 루트 디스크

- [ ] EC2 > 볼륨 목록을 새로고침함
- 왜 이 순서: 루트 볼륨은 서버가 종료될 때 함께 지워지게 되어 있음. 그래서 서버 종료 뒤에 확인함.
- 화면에서 확인할 것: "3. 정리 전 준비"에서 적은 볼륨 ID가 목록에 없음. 목록이 비어 있음.
- 만약 남아 있으면: 상태가 "사용 가능(available)"인지 보고 볼륨 선택 > 작업 > 볼륨 삭제. 지운 뒤 목록을 다시 확인함.
- 증빙: `e05-volumes-empty.png`
- 권한: `ec2:DeleteVolume` 허용됨 (남은 볼륨이 있을 때만 필요).

- [ ] EC2 > 보안 그룹 > `b3-1-web-sg` (`sg-0b65376c4e71e9d39`) 선택 > 작업 > 보안 그룹 삭제
- 왜 이 순서: 서버에 붙어 있는 동안에는 지울 수 없음. 단계 1 다음에 해야 함.

- 권한: `ec2:DeleteSecurityGroup` 허용됨 (`b3-1-vpc` 안의 보안 그룹만).

### 단계 4. 키 페어 삭제 — `b3-1-ec2-key`

- [ ] EC2 > 키 페어 > `b3-1-ec2-key` 선택 > 작업 > 삭제
- [ ] 내 컴퓨터: 저장소의 `.ssh/` 폴더에 있는 `b3-1-ec2-key` 개인 키 파일을 삭제함 (파일을 열지 말고 지우기만 함)
- 왜 이 순서: 서버가 없어졌으니 더 이상 SSH 접속에 키가 필요 없음. 키 페어는 돈이 들지 않지만, 쓰지 않는 열쇠는 남기지 않음.
- 화면에서 확인할 것: 키 페어 목록에 `b3-1-ec2-key`가 없음. 내 컴퓨터 `.ssh/` 폴더에 키 파일이 없음.

- 주의: ID가 `igw-01fa7271de8df9da6`(기본 VPC 것)이 아닌지 다시 확인함.

- 왜 이 순서: 서브넷에 연결된 동안에는 지울 수 없음. 단계 7에서 연결이 풀렸음.
