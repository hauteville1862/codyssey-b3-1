# 모의평가 답변

## B3-1-E06

> 외부 → IGW → Subnet → EC2로 이어지는 네트워크 흐름을 다이어그램 기준으로 설명할 수 있는가?

네, 다이어그램을 보면서 설명드리겠습니다.

제 노트북에서 웹사이트 주소를 열면, 요청은 먼저 VPC 입구에 있는 인터넷 게이트웨이에 도착합니다. 인터넷 게이트웨이는 그 요청을 VPC 안쪽 서브넷에 있는 서버로 넘겨 줍니다. 서버 앞에는 보안 그룹이 있는데, 웹 요청인 80번은 허용해 두었으니까 들어갑니다. 그러면 서버가 웹페이지를 돌려줍니다.

돌려줄 때는 라우팅 테이블을 봅니다. 라우팅 테이블에 "VPC 밖으로 가는 건 인터넷 게이트웨이로 보내라"라고 적혀 있어서, 답이 인터넷 게이트웨이를 지나 제 노트북으로 돌아옵니다.

실제로 노트북에서 열었을 때 페이지가 뜬 화면은 E04에 있습니다. 이상입니다.

## B3-1-E07

> 보안 그룹 규칙을 어떤 기준으로 최소화했는지(허용/미허용 포트) 설명할 수 있는가?

네, E03의 인바운드 규칙 화면을 보면서 설명드리겠습니다.

먼저 포트를 짧게 말씀드리면, 서버 안에는 요청을 기다리는 프로그램이 여러 개 있습니다. 요청에 붙은 포트 번호를 보고 어느 프로그램에게 갈지 정해집니다. 보안 그룹은 어떤 포트로 오는 요청을 들여보낼지 정합니다. 그중 인바운드 규칙은 밖에서 서버로 들어오는 요청 중 무엇을 들여보낼지 정한 목록입니다.

이 목록은 화이트리스트 방식입니다. 화이트리스트는 "목록에 적힌 것만 허용하고, 나머지는 전부 막는다"는 뜻입니다. 보안 그룹에는 "이건 막아라"라는 규칙이 따로 없고, 허용할 것만 적습니다. 그래서 목록이 짧을수록 열린 곳이 적어집니다.

제 기준은 "꼭 필요한 포트만 적는다"였습니다. 그래서 인바운드 규칙은 두 개뿐입니다. 누가 들어올 수 있는지는 각 규칙의 "소스" 칸으로 정했습니다.

첫째는 80번 포트입니다. 웹 서버인 Nginx가 받는 포트입니다. 웹사이트는 모두가 봐야 하니까, 소스를 "어디서든"으로 골랐습니다. 그러면 소스가 0.0.0.0/0이 되는데, 세상의 모든 주소라는 뜻입니다.

둘째는 22번 포트입니다. 서버에 원격으로 접속하는 SSH가 받는 포트입니다. 관리는 저만 하면 되니까, 소스를 "내 IP"로 골랐습니다. 그러면 AWS가 지금 접속한 제 컴퓨터의 주소를 슬래시 32로 자동으로 넣어 줍니다. 슬래시 32는 딱 그 주소 하나라는 뜻입니다.

나머지 포트는 목록에 적지 않았으니 자동으로 막힙니다. 데이터베이스 포트나 다른 포트는 이번 실습에서 쓰지 않기 때문입니다. 모든 포트를 한꺼번에 여는 규칙도 만들지 않았습니다.

이상입니다.

## B3-1-E08

> 외부 접속 검증을 A 또는 B 중 무엇으로 선택했고, 그 선택을 위해 무엇을 어떻게 구성했는지 설명할 수 있는가?

저는 B를 주로 썼고, A도 해 봤습니다. B는 다른 분들 사례를 보고 골랐습니다. 해 보니 B가 더 확실했습니다. 항상 "OK"라는 똑같은 답이 와서, 성공했는지 바로 알 수 있었기 때문입니다.

준비는 세 가지를 했습니다. 먼저 노트북 터미널에서 SSH 명령어와 키 파일로 서버에 접속했습니다. 그리고 명령어로 웹 서버 프로그램인 Nginx를 설치하고 실행했습니다. 다음으로 보안 그룹에서 웹용 80번 포트를 열었습니다. 마지막으로 서버가 인터넷 주소를 받도록 직접 켰습니다.

A는 이걸로 끝입니다. 브라우저로 서버 주소를 열면 Nginx 기본 페이지가 뜹니다.

B는 하나를 더 했습니다. Nginx 설정 폴더에 "/health로 오면 OK라고 답해라"라는 규칙 파일을 하나 만들고, 검사한 뒤 다시 읽게 했습니다.

그다음 제 노트북에서 /health를 불렀더니 200 OK와 OK가 왔습니다. 그 화면이 E04에 있습니다. 이상입니다.

## B3-1-E09

> 실습 리소스를 추적/정리하기 위해 어떤 기준(태그, 이름 규칙, 체크리스트)을 사용했는지 설명할 수 있는가?

네, README의 "리소스 추적 기준"과 정리 체크리스트를 보면서 설명드리겠습니다.

기준은 두 가지를 썼습니다.

첫째, 이름입니다. 이번 실습에서 만든 건 전부 이름이 "b3-1"로 시작합니다. 그래서 목록에서 이름만 봐도 내 실습 리소스인지 바로 알 수 있습니다. AWS에는 처음부터 있던 기본 VPC도 있는데, 그건 이름이 없어서 헷갈리지 않습니다.

둘째, 체크리스트입니다. 만든 리소스의 ID를 README 표에 적어 두었습니다. 정리할 때는 이 ID와 체크리스트를 하나씩 맞춰 보면서 지웁니다. 체크리스트에는 서버, 디스크, 고정 IP, 인터넷 게이트웨이, VPC처럼 돈이 나갈 수 있는 것들이 들어 있습니다.

이상입니다.
